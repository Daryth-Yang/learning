- **节奏**:作为副线,分 4 讲,每讲 30-60 分钟,穿插在 AI 主线之间。

## 📝 各讲要点(讲完后填充 Daryth 的理解 + 归档)

### 第 1 讲:看懂代码项目的骨架
- 目标:打开任意一个代码仓库,能说出"这个文件夹大概装什么"
- 核心三件事:① 目录约定(src/dist/packaging…)② 文件类型(.json/.py…)③ JSON 长啥样、怎么读
- D5 实战锚点:用 AI Slides 或 Clawtics 的真实目录结构当例子
- ✅ **归档结论(2026-06-09)**:用"代码项目=有命名约定的设计文件"类比切入,效果好。
  - Daryth 复述全对:src=人写源代码 / dist=机器导出成品(她自创"源文件 vs 导出成品"类比)
  - JSON 实战:读按钮配置,唯一踩坑 = 把 `disabled` 误读为"失败"、把 `true/false` 当"显示内容";已校准为"true/false 是在回答前面字段的是否"
  - 用设计师"按钮禁用态/置灰态"类比讲 disabled,她秒懂
  - 顺带预告了 Q10(.exe vs .zip,留第3讲)

### 第 2 讲:命令行 & 构建脚本
- 目标:看懂工程师/AI 让你敲的命令在干嘛
- 核心:① 命令行=打字下命令(GUI点菜单 vs 命令行喊厨师)② build script=src→dist 自动食谱 ③ `--xxx` 参数=点菜附加要求 ④ 进程/前台/后台
- ✅ **归档结论(2026-06-09)**:
  - 三个复述(build脚本作用 / --clean / src vs dist)全对
  - **亮点**:她主动追问"src和dist不都是代码吗",触及"为什么要构建"的本质 → 用 Figma 源文件 vs 导出PNG 讲透"加工前/后、人友好/机器友好"
  - 又追问 `npm run dev`,顺势串起 JSON(package.json)+命令行+进程,三讲打通
  - 后台进程:她自悟"前台关≠后台进程被杀",理解有深度
  - ⚠️ **纠正易混点**:她把"后台 background"写成"后端 backend" → 已讲清"台=前后舞台(可见性)/ 端=前后端(代码分层)";以后留意她是否还混
- 🔁 **npm 深挖(她主动追问 3-4 轮,第2讲延伸)**:第一次讲太绕(应用商店+快捷指令+包管理一起上),砍到"npm=程序员的应用商店"单点才通。
  - 教训:她卡住时**砍到一个最小类比**比堆多个类比有效
  - 最终她能自述完整闭环:**package.json(购物清单)→ npm install(照单采购)→ node_modules(橱柜)**;包来自 npm 在线大超市
  - "包(package)"用她的"现成素材包/组件库"类比秒懂;Node(n)按"了解就行"略过

### 第 3 讲:软件怎么"打包发出去"
- 目标:看懂软件交付的两种形态 + 安装包怎么来的
- 核心:① .zip=解压即用散装版 ② 安装包=带"下一步"向导自动装好(注意区分"程序本体.exe"vs"安装程序.exe")③ Inno Setup=做安装向导的工具
- ✅ **归档结论(2026-06-09)**:
  - 复述清楚 .zip vs 安装包、Inno Setup 用途
  - **PM 亮点**:决策题"textpolish 发同事选哪个",她选安装包,理由="同事不用自己解压找位置,有引导更轻松"——**自发用了"用户体验视角"做决策**
  - 教练补了"权衡的另一面"(内部频繁改版 .zip 更快),强化"决策=权衡、要有理由"的 PM 思维
